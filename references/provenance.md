# 来源与证据边界

本技能整理了 2026-10-12—13 的真实协作、桥接恢复和直聊开发经验。公开版保留机制、参数、症状、判断依据、修复和限制；删除个人用户名、服务器身份/地址、私人路径、私有会话/对话 ID、测试标记及项目业务内容。

## 发布内容与来源

- 模式 A 来自获授权的固定 Claude Code 主管会话、Codex 桥接脚本和历史公开回执；保留 17 类桥接/运行故障。
- 模式 B 提供 assets/direct-chat/ 源码、配置示例和离线测试；新增 5 类直聊实践，涵盖生命周期竞态、首次失败接续、系统提示快照、命令权限与专有接口边界。
- [故障与实践索引](incident-playbook.md) 共 22 个编号条目；预防措施和静态发现没有冒称实际生产故障。
- [CLI reference](https://code.claude.com/docs/en/cli-reference) 与 [programmatic usage](https://code.claude.com/docs/en/headless) 是参数解释参考；特定渠道的型号/effort 和版本能力以实际配置、CLI 接受及响应标签区分，不用官方文档替代部署证据。

历史脚本名如 connect.py、implementation_bridge.py、dialogue_archive.py、resume_dispatch.py、worker_public_stream_v2.py、claude_usage_pty_readonly.py 作为机制来源保留；除 assets/direct-chat/ 内明确提供的文件外，原脚本、记录和诊断产物不随包发布。文档中的历史文件名/行号是来源定位信息，不是承诺发布包内有相同路径，不需要连接私人服务器才能理解说明。

不得发布 SSH 私钥、API key、账号认证文件、原始调试日志、会话全文、真实 SID/request UUID、nonce、截图、私有项目数据库、运行状态或配置副本。示例 host/path 是占位，模型名是来源渠道的请求/返回标签，不是身份认证声明。

## 已保留的角色变化

早期协作曾由 Codex 统筹并咨询 Claude，后来由用户明确改为 Claude 主管、Codex 只桥接执行。模式 A 保留最后分工，不把早期职责同时叠加为另一套审批机制。用户后来直接聊天的需求形成模式 B，运行时没有 GPT/Codex 转述，也不自动接管旧主管会话。

项目业务目标、资金/账户、材料外发、具体供应商限制和持续调度许可没有移植为通用政策。已有授权在原会话有效，不自动成为新项目的身份或执行授权。

## 历史经验没有被精简掉

- 原 ID/hash 幂等恢复与新 UUID/attempt 的区别；unknown 确认终止、not_found 未登记是两种不同持锁证据出口。
- 主管/v1/v2 协议及预算差别；v2 两 Python 文件、12000 字符、首公开 300 秒、END+AST 和 partial 恢复。
- 124、预算附近 -9、提前 -9、零正文与 token 未知；不把格式修复额度挪去执行超时。
- collector 正常 45 秒、退避 60/120 秒、连续三次只停收件；原 t0、计数、终态保留。
- 旧归档白名单缺 usage/manifest/attempt，v2 远端补同步缺覆盖，不宣称全量原件齐全。
- 隔离 PTY 内置 /usage、不 resume 主管、ANSI/选中项解析；单请求 usage、会话累计值与额度分开。
- 实际路由与归档标签同步、旧本地源码可能落后；UTF-8 stdin、空 argv、JSON 不等于 shell 转义。
- 容器入口、持久挂载、实际 datadir/userdir/dbpath、输入 manifest 与运行版本对应。

后续更新以新证据增加或修正结论，保留旧失败和阶段事实。不要把历史 PID、额度、日期、模型分工当当前默认；也不要为“更简洁”删除持锁范围、停止条件和实际能力缺口。
